# 软件实现落地说明

开发依据为 `软件实现.md` 第 1594 行起最后一轮想法：仅电脑本地使用、数据加密、Agent 通过接口记账、Python 在本地做分析、软件直观看数据；语音识别与手机端不纳入当前范围。

## 代码放在哪里

选择直接扩展 **`PersonalLedger/Bastide`**，没有新建第三套记账项目。

- `yuan1/moneymanagerex` 是 C++/wxWidgets 桌面程序，已有复杂桌面功能和数据库加密，但不是 Python API 架构。为了接 Workbuddy 而再维护独立明文分析副本，不符合需求。
- `PersonalLedger/Bastide` 已有 Python/FastAPI、SQLAlchemy、账户/分类/交易、整数金额和余额缓存，可直接复用。原版交易接口偏向导入后的查询和分类修改，个人模式补齐了手工新增、完整修改、删除和转账。
- 在原仓库内增加独立的个人模式入口，复用原 ORM/余额函数/迁移，同时保留原版 Flutter 应用。个人模式不使用原版明文数据文件。
- 没有把 MMEX 的 GPL C++ 加密代码混进 Python 项目；MMEX 支持通过兼容 CSV 迁移，避免混用两种不兼容的加密数据库。

## 现在怎么使用

双击 `PersonalLedger/启动个人账本.cmd`。默认会打开本机 `http://127.0.0.1:8899`。

首次创建时由你设置主密码并保存恢复密钥；开发过程中没有创建真实账本、预设主密码或替你配置真实的 Workbuddy 令牌。

完整使用说明在 **`PersonalLedger/docs/personal.zh-CN.md`**，包括启动、接口、Workbuddy MCP 配置、CSV 导入、加密备份和 Python 分析。

## 对应需求的实现

| 需求 | 实现位置 |
| --- | --- |
| 独立本地软件入口 | `PersonalLedger/启动个人账本.cmd`、`backend/app/personal_cli.py` |
| 中文可视化 | `backend/app/features/personal/static/` |
| 加密账本与恢复 | `backend/app/features/personal/vault.py` |
| 账户/分类/交易/转账 | `backend/app/features/personal/repository.py`，复用原 Bastide 模型 |
| Python 本地统计 | `backend/app/features/personal/analysis.py`、`tools/analyze_personal.py` |
| Workbuddy 工具接口 | `backend/app/personal_mcp.py`、`backend/app/personal.py` |
| 批量分类及撤销 | `personal_actions` / `personal_drafts` 迁移与业务实现 |
| 微信/支付宝/MMEX CSV | `backend/app/features/personal/imports.py`、`data_repository.py` |
| 自动化验证 | `backend/tests/features/personal/`、`tools/test_personal_browser.cjs` |

使用“加密容器＋内存 SQLite”，不是 SQLCipher。静态文件使用成熟密码库的 AES-256-GCM，密码密钥派生使用 Argon2id；每次成功记账已加密落盘。这样无需额外编译 Windows SQLCipher，也避免为 Python 分析另存明文库。

## 明确边界

当前使用本机浏览器作为桌面界面，未生成 Windows EXE 安装包；基础界面与 Agent 接口均由本机 Python 服务提供，不要求安装 Flutter 开发工具。微信/支付宝实现的是可靠的账单文件导入，未伪装成已经能监听个人支付后的实时回调。

原始 `软件实现.md` 未改动。功能源码修改保留在 `PersonalLedger` 中，可按正常 Git 流程审查、提交、推送；本次不自动上传云端，也不会把账本或令牌加入 Git。
